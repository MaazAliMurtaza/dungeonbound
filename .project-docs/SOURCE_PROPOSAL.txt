P4: 1. Introduction
P5: Dungeonbound is a lightweight 2D mobile role-playing game (RPG) designed for Android devices, particularly low-to-medium-end devices. The game focuses on gameplay mechanics, procedural dungeon generation, strategic turn-based combat, character progression, and resource-efficient design rather than high-end graphics.
P6: Players will explore dynamically generated dungeons containing combat encounters, treasure, events, and boss battles. As players progress, they will gain experience, acquire new equipment, unlock abilities, and improve their character.
P7: The application will be developed using React Native with TypeScript. A Node.js backend with PostgreSQL will be used for user accounts, character progression, inventory persistence, quests, achievements, and leaderboards.
P8: 2. Problem Statement
P9: Many modern mobile RPGs rely heavily on high-resolution graphics, 3D environments, complex animations, and continuous resource consumption. Such games can require relatively powerful hardware and large amounts of storage and memory.
P10: At the same time, simpler RPGs may lack procedural gameplay, meaningful character progression, or strategic combat mechanics.
P11: Therefore, there is an opportunity to develop a lightweight mobile RPG that provides substantial gameplay depth while minimizing graphical and computational requirements.

P21: 3. Proposed Solution
P22: The proposed solution is a 2D turn-based roguelite RPG where players repeatedly explore procedurally generated dungeons. A typical gameplay cycle consists of login, character selection, dungeon generation, room exploration, combat/events/treasure, rewards, boss battles, progression, and saved progress.
P23: The game will prioritize gameplay mechanics over graphical complexity, allowing it to run on low-to-medium-end Android devices.

P34: 5. Main Features
P35: 5.1 Procedural Dungeon Generation
P36: Instead of manually creating every dungeon, the application will generate dungeon layouts dynamically. Each dungeon can contain combat, treasure, event, elite enemy, and boss rooms. The generation algorithm will ensure that every dungeon contains a valid path from the starting point to the boss while introducing variation between runs.
P37: This allows the game to provide many different dungeon experiences without requiring hundreds of manually designed levels.
P38: 5.2 Turn-Based Combat and Enemy AI
P39: Combat will be turn-based, allowing players to make strategic decisions. Players will be able to perform normal attacks, use special skills, defend, and use consumable items.
P40: Enemies will use rule-based AI. For example, an enemy may defend when its health is critically low, use a strong attack when the player's health is low, or perform a normal attack otherwise. Different enemy types will have different behavior patterns.
P41: 5.3 Character Progression and Skill System
P42: Players will earn experience points from battles and quests. When enough XP is accumulated, the player will level up and improve their character.
P44: The game will initially provide three classes:
P45: Warrior — high health and defense.
P46: Ranger — high speed and critical-hit probability.
P47: Mage — lower physical defense but strong magical attacks.
P48: Players will also be able to unlock skills through a simple skill tree, allowing different character builds and play styles.
P49: 5.4 Inventory, Equipment and Loot System
P50: Players will collect weapons, armor, accessories, consumables, and other items. Items will have different rarity levels such as Common, Rare, Epic, and Legendary.
P51: Loot will be generated according to predefined probability rules, meaning that completing a dungeon can produce different rewards each time.
P52: 5.5 Quest, Achievement and Persistent Progress System
P53: Players will receive quests and earn rewards. The application will also provide achievements such as First Dungeon, 100 Enemies Defeated, Boss Slayer, Level 10, and Legendary Hunter.
P54: Player progress will be stored in the backend so that progress is not lost when the application is closed. An optional leaderboard will allow players to compare their progress.

P71: 8. System Architecture
P72: The proposed architecture consists of a React Native mobile application communicating with a Node.js/Express backend through REST APIs. PostgreSQL will store persistent application data.
P73: Core gameplay calculations such as dungeon generation and combat can run locally to minimize network dependency and improve responsiveness. The backend will primarily handle authentication and persistent data such as characters, inventory, quests, achievements, and leaderboard information.

P175: 16. Project Summary
P176: Dungeonbound is a lightweight, procedurally generated 2D mobile RPG developed using React Native and TypeScript. The game focuses on strategic turn-based combat, procedural dungeon generation, rule-based enemy AI, character progression, equipment, randomized loot, quests, and persistent player progression. Unlike graphics-intensive RPGs, Dungeonbound will use a resource-efficient 2D design and lightweight game mechanics to support low-to-medium-end Android devices. A Node.js/Express backend and PostgreSQL database will manage authentication, player progression, inventory, quests, achievements, and leaderboard data.
